# Opportunity Database Operating Model

## Record lifecycle

1. **Capture** — record a raw observation without prematurely naming an opportunity.
2. **Normalize** — classify the observation as a problem, workflow, capability, constraint, source, or other entity.
3. **Connect** — link entities and record relationship confidence.
4. **Research** — create only the questions that could change the decision.
5. **Formulate** — create an opportunity record with explicit assumptions.
6. **Evaluate** — compare fit, access, value, effort, risk, and learning value.
7. **Validate** — run the cheapest credible experiment.
8. **Decide** — select, defer, reject, or reformulate.
9. **Learn** — update the database and Person Atlas from the result.

## Opportunity stages

`candidate → researching → evaluating → validating → selected → building → reviewed`

Alternative outcomes: `deferred`, `rejected`, `superseded`.

## Promotion rule

An opportunity advances only when evidence, strategic fit, and a justified next investment support promotion.

## Required fields for promotion

- clear problem and affected actor;
- current alternative or workaround;
- opportunity mechanism;
- evidence links;
- key assumption;
- kill signal and continue signal;
- next action and owner.
