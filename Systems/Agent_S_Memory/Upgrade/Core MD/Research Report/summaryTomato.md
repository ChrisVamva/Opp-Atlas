# Orange Tomato Vault Summary

## What this folder is
This folder is an **editorial operating system** for **Orange Tomato**, a brutalist publication focused on:
- agentic infrastructure
- automation tooling
- open model stack shifts
- displacement of legacy SaaS and brittle workflows
- technical research, ghostwriting, and publication workflows

The project’s voice is deliberately hard-edged: **no fluff, no generic AI hype, no soft conclusions**. The intended reader is a technical operator already running autonomous or semi-autonomous systems.

## Core identity of the project
Across the notes, Orange Tomato is consistently defined by a few fixed principles:
- **Start with the thesis**; never open with filler
- Prefer **technical nouns over adjectives**
- Treat legacy SaaS, wrappers, and selector-heavy automation with skepticism
- Focus on **systems that remove human overhead**
- End tool evaluations with a **Tomato Score** verdict

The recurring value test is whether something is:
- **self-hostable**
- **API-first**
- **goal-oriented / agent-ready**
- less brittle than legacy UI-driven tooling

## Main themes found in the files
### 1. Editorial system and voice control
Several files define the publication’s identity and enforce consistency:
- `SITE_IDENTITY MD.md`
- `ghostwriter_Orange Tomato_MD.md`
- `🍊ORANGE TOMATO — PROJECT SYSTEM PROMPT🍊.md`
- `CREATE THE PROJECT.md`

These documents establish:
- the Orange Tomato manifesto
- banned words and phrases
- audience definition
- category definitions
- required article structures
- SEO variables to confirm before writing
- a per-session input template for ghostwriting

This means the folder is not just a note collection. It is a **content production framework** for making AI-assisted writing sound like a specific operator with a specific worldview.

### 2. Research and article production workflow
Another major cluster of files defines how topics should be selected, researched, filtered, and handed off for writing:
- `🍊Daily Workflow🍅.md`
- `📋Operator Checklist📋.md`
- `🕷️Daily SOP Step-by-Step🔌.md`
- `📋CLAUDE HANDOFF ORANGE TOMATO ARTICLE PACK📋.md`
- `LUX first Oficial Handoff pack to Claude.md`
- `Suggestions for Orange Tomato Openclaw.md`
- `Must cover today Open model stack is getting more serious, not less.md`

The workflow they describe is broadly:
1. choose a topic slate for the day
2. run cheap discovery first
3. escalate to better sources only when needed
4. extract structured evidence
5. build a research pack
6. hand the pack to Claude for drafting
7. review for brand fit and evidence quality

The emphasis is on **signal density, primary sources, structured evidence, and clear separation of fact from inference**.

### 3. Publication strategy and roadmap
A third cluster is about turning Orange Tomato into a durable product or platform:
- `🍊Strategic Roadmap & Architecture Audit🍊.md`
- `🍅Orange Tomato Restoring Publication Features & Data Layer🍅.md`
- `🍊The Omega 5 To-Do List🍊.md`
- `🎯Weekly Briefing🔄.md`

These documents show that Orange Tomato is not only a writing project. It is also a **site / product / research platform** in development.

Key product directions mentioned:
- restoring publication features in a React/Vite/Tailwind stack
- creating a structured post data layer
- adding search, categorization, and relational content logic
- moving toward dynamic routing and better information architecture
- building a sovereign, self-hosted intelligence system
- eventually supporting agentic chat, ingestion pipelines, and local search

### 4. Tool universe being tracked
The folder also includes lists and templates for tracking tools and sectors of interest, especially around:
- browser automation
- agent frameworks
- orchestration systems
- scrapers
- data tools
- UI automation
- repo/cloud agents

Examples named in the notes include n8n, Browser Use, Skyvern, Firecrawl, Exa, DuckDB, Windmill, Activepieces, Devin, Jules, Gemma 4, CrewAI, LangGraph, OpenHands, and many more. The editorial lens is usually: **does this tool actually reduce fragility and human-in-the-loop overhead, or is it just another wrapper?**

## Gaps or unfinished parts
A few files explicitly show that the system is not fully finalized yet.

The biggest unfinished items are in `🍊ORANGE TOMATO — PROJECT SYSTEM PROMPT🍊.md`:
- a confirmed **voice fingerprint** written by the operator
- **five raw tool opinions** for calibration
- a fixed **technical depth floor** for the audience

So the system is already well-structured, but still waiting for a few human calibration inputs before it becomes fully operational as a consistent ghostwriting engine.

## Overall takeaway
This folder is best understood as a **combined editorial doctrine + research workflow + ghostwriting system + publication roadmap** for Orange Tomato.

It contains four layers working together:
1. **Brand doctrine** — what Orange Tomato believes, how it sounds, what it rejects
2. **Research operations** — how topics are chosen, validated, and turned into evidence packs
3. **Writing infrastructure** — prompts, templates, score systems, and handoff formats for Claude
4. **Product/platform planning** — how the website and underlying content system should evolve

In plain terms: this is a serious attempt to build **a repeatable machine for producing high-signal writing about agentic systems and automation infrastructure**, with a strong anti-fluff identity and a bias toward self-hosted, API-first, selector-killing tools.
